# V2 Plan: Daily Truth `universe.json` (Immutable 3-Step Workflow)

## Summary
Implement a breaking v2 where `universe.json` is the only source of truth for universe control, driven only by input `symbols + start_date + end_date`.
The file stores one-day snapshots (`daily_snapshots`) showing what is active that day and what is missing that day.
Workflow is strictly separated:
1. `define` creates/overwrites `universe.json` (only writer, with explicit `force`).
2. `download` reads `universe.json` and builds strict day-symbol download plan.
3. `export` reads `universe.json` and exports/report only.
No `download`/`export` mutation of `universe.json`.

## Final V2 Schema (No `active_symbols_union`)
Stored by `/Users/min/Developer/Xdata/src/cryptoservice/models/universe.py`:

```json
{
  "schema_version": "2.0",
  "requested_symbols": ["BTCUSDT", "ETHUSDT"],
  "start_date": "2024-10-01",
  "end_date": "2024-10-31",
  "daily_snapshots": [
    {
      "date": "2024-10-01",
      "active_symbols": ["BTCUSDT"],
      "missing_symbols": {
        "ETHUSDT": "not_available_on_date"
      }
    }
  ],
  "created_at": "2026-02-21T00:00:00+00:00",
  "description": "optional"
}
```

Contract:
1. `daily_snapshots` has exactly one entry per day in `[start_date, end_date]`.
2. `active_symbols` and `missing_symbols.keys()` partition `requested_symbols` for each day.
3. `missing_symbols` is symbol -> reason map.
4. `active_symbols_union` is removed entirely (derived when needed).

## Failure Modes and Edge Rules
1. API/network failure during define daily checks: fail define, write nothing.
2. Invalid/unknown symbols: represented in each day’s `missing_symbols` (not dropped from `requested_symbols`).
3. Days with zero active symbols are valid and must remain in file.
4. Download/export must tolerate empty daily active sets and produce zero-task/partial reports cleanly.

## Test Cases and Scenarios
1. Model/schema tests:
   1. v2 roundtrip serialize/load.
   2. day continuity and exact count.
   3. partition invariant (`active + missing == requested`) per day.
   4. v1 file rejection.
2. Define tests:
   1. normalization/dedup of requested symbols.
   2. correct day-level active/missing classification.
   3. immutability behavior (`force` vs no `force`).
   4. hard failure on API error with no file write.
3. Download tests:
   1. strict day-symbol plan generation from daily snapshots.
   2. no universe file mutation.
   3. correct summary counts by day and symbol.
4. Export tests:
   1. expected coverage derived from daily snapshots.
   2. merged missing reports remain correct.
   3. no universe file mutation.
5. CLI tests:
   1. argument validation for define/download/export.
   2. exit codes and error messaging for immutable file/API failures/schema errors.

## Assumptions and Defaults
1. v1 -> v2 is immediate breaking change; no compatibility shim.
2. Path is caller-defined in define and reused in download/export.
3. `daily_snapshots`, `date`, `active_symbols`, `missing_symbols` are final names.
4. `active_symbols_union` is intentionally removed from persisted schema.
